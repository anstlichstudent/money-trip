Trip expense database

One trip. Six participants. One manager. Shared expenses and recorded payments use the same data to calculate each participant’s balance.

Data rules

Receipt input

input_json keeps the validated receipt input: item name, unit price, quantity, participant IDs, item discount, bill discount, tax and service charge. Shared costs keep the amount and selected participant IDs. Percentages use integer basis points: 10% = 1000.

The JSON is the input record. expense_shares stores the calculated result. No separate item tables are required for this version.

Database checks

Composite foreign keys include trip_id to prevent references to another trip. Money is an integer within the JavaScript safe range. Payment amounts are positive. Sender and receiver must differ.

Participant order is unique within a trip. An expense and participant pair has at most one share.

Application checks

Require six participants at setup and at least one share per expense. Validate JSON structure, positive integer quantities, discounts, input limits and all calculation results. The sum of shares must equal the expense total.

Save expense, shares and request result in one atomic D1 batch. Version checks must reject stale edits. Reject reuse of a request ID with different input or operation.

Access and deletion

The manager password hash and MCP token stay in Worker secrets. Viewer tokens give read access only. Sessions do not belong to participants.

Deleting an expense deletes only its shares. Payments remain. Trip and participant deletion is restricted when records still refer to them. Request results have no expense foreign key so retry records remain after deletion.

Balance is calculated

balance = expenses paid − expense shares + payments sent − payments received
Positive: still to receive. Negative: still owes. Zero: settled.

Transfer suggestions use the final balances and fixed participant order. Do not store a balance table or a second list of debts. Check safe integer limits for trip totals as well as individual records.
